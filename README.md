## Назначение

Набор инструментов для повседневной работы с шиной. Одни закрывают то, чего
в веб-интерфейсе FESB нет, другие делают привычные операции быстрее или сразу
по многим доменам. Пригодится не всё и не всем: это не замена веб-интерфейсу
и не попытка его повторить.

Набор растёт по рабочим задачам. Операция, которую регулярно приходится
собирать из десятка действий в интерфейсе шины, становится здесь отдельным
инструментом.

Два режима работы: папка выгрузки конфигурации (или её ZIP) и живой сервер
по REST API.

## Возможности

- **Массовая правка трассировки** — брокер, очередь и режим сразу во многих
  доменах. Значения в `domain.xml` заменяются по точным смещениям, поэтому
  форматирование, порядок атрибутов и BOM остаются прежними. Рядом кладётся
  копия файла, после отправки идёт сверка.
- **Отчёт по точкам входа и выхода** — адреса, которыми шина говорит наружу:
  схема, порт, TLS, шифры, авторизация, состояние, потоки Jetty. Локальные
  очереди — с менеджером, который их держит. Выгрузка в Excel.
- **Трассировка по всему серверу** — какие СОПС трассируются и через какие
  объекты, включая остановленные домены. Отобранные СОПС запускаются,
  останавливаются и обнуляют счётчики разом.
- **Инвентаризация стенда** — домены и СОПС со счётчиками, схемы маршрутов,
  связи «кто кого вызывает» по адресам концов, незавершённые обмены.
- **Очереди** — менеджеры QMS, QME и RQMS, их очереди и сообщения, поиск
  по телу сообщения.
- **Безопасность стенда** — сертификаты хранилищ с остатком срока действия,
  роли и права словами, активные сессии, настройки входа.
- **Журналы и аудит** — с разбором на уровень, источник и текст.
- **Клиент AMQP** — отправка с заготовками, переменными, пачками и CSV, приём
  с отбором и записью, просмотр и чистка очередей, переливка сообщений между
  брокерами, клиенты брокера, история и статистика. Брокер задаётся в профиле
  стенда рядом с адресом шины.
- **Сравнение двух стендов** — домены, СОПС и константы. Только чтение.
- **Обслуживание** — модули, точки восстановления, запуск и остановка доменов.
  Константы трёх уровней правятся на месте, по всему стенду ищутся по значению
  и заменяются массово с предпросмотром.

Интерфейс двуязычный (русский, English), светлая и тёмная темы.

## Как работает

Приложение обращается только к тому адресу, который ввели: своих серверов
и телеметрии у него нет. Подключения хранятся на машине пользователя, пароль
записывается только с явного разрешения.

Отдельных методов для объектов трассировки в API шины нет, поэтому режим API
устроен через выгрузку и загрузку доменов: `GET /api/domains/export/archive`,
правка файлов, `POST /api/domains/import/archive`, сверка. Выгрузка идёт
пачками в несколько параллельных запросов — шина собирает архив целиком
до начала передачи.

## Установка

Готовые сборки — в [релизах](https://github.com/DEADover/FESB-Toolkit/releases):
Windows x64 (NSIS, MSI, портативный exe) и macOS на Apple Silicon (dmg).
Из зависимостей нужен только WebView2 Runtime, он есть в Windows 10/11.

Дальше — либо папка выгрузки, перетащенная в окно, либо подключение к серверу:
узел и порт (по умолчанию 8181), схему и `/manager` приложение подставит само.

## Сборка из исходников

Нужны [Node 20+](https://nodejs.org) и [Rust 1.82+](https://rustup.rs):

```bash
git clone https://github.com/DEADover/FESB-Toolkit
cd FESB-Toolkit
npm install
npm run dev            # разработка
npm run build          # сборка под текущую систему
npm test && npm run test:rust
```

## Стек

Tauri 2 · Rust · React 19 · TypeScript · Vite · Tailwind

Работа с файлами и сетью целиком в Rust, интерфейс получает готовые структуры
и прямого доступа к диску не имеет. Разбор XML, сборка архивов и запись `.xlsx`
свои, без внешних библиотек.
