## Зачем это

Веб-интерфейс FESB рассчитан на работу с одним доменом за раз. Когда доменов
двести пятьдесят, простые вопросы становятся дорогими: **на какой брокер
смотрит трассировка во всех СОПС сразу, через какие адреса шина разговаривает
с внешним миром, что застряло прямо сейчас и когда истекает сертификат.**

Инструмент отвечает на них за один экран и не заменяет веб-интерфейс — он
закрывает то, что там делается руками по одному домену. Два режима: папка
выгрузки конфигурации (или её ZIP) и живой сервер по REST API.

## Что внутри

- 🎯 **Массовая правка трассировки** — брокер, очередь и режим сразу в сотнях
  доменов. Значения в `domain.xml` заменяются по точным смещениям, поэтому
  форматирование, порядок атрибутов и BOM остаются байт-в-байт прежними. Копия
  файла кладётся рядом, сверка после отправки проверяет, что доехало.
- 🔌 **Отчёт по точкам входа и выхода** — все адреса, которыми шина говорит
  наружу: схема, порт, TLS, шифры, авторизация, состояние и потоки Jetty.
  Локальные очереди — с менеджером, который их держит: из параметров адреса,
  `settings.properties` домена или общих свойств брокера. Двадцать четыре
  столбца, выгрузка в Excel; отчёт собирается полторы минуты и потому
  остаётся на диске.
- 🔎 **Трассировка по всему серверу** — какие СОПС трассируются и через какие
  объекты, включая остановленные домены. Один запрос вместо выгрузки
  конфигурации: 2293 СОПС из 255 доменов за 289 мс. Отобранные фильтрами
  СОПС запускаются, останавливаются и обнуляют счётчики разом.
- 🗺 **Инвентаризация стенда** — домены и СОПС со счётчиками, схемы маршрутов
  слева направо, связи «кто кого вызывает» по адресам концов, незавершённые
  обмены с шагом и потоком.
- 📨 **Очереди** — менеджеры всех трёх видов (QMS, QME, RQMS), очереди и
  сообщения. Поиск идёт и по телу: шина отдаёт его по одному сообщению за
  запрос, поэтому за телами инструмент ходит пачками.
- 🔐 **Безопасность стенда** — сертификаты хранилищ с остатком дней до
  истечения, роли и права словами вместо кодов, активные сессии и настройки
  входа: устаревший хеш пароля и «подойдёт любой» отмечаются отдельно.
- 📋 **Журналы и аудит** — разобранные на уровень, источник и текст; кто и что
  менял на сервере.
- 📮 **Брокеры AMQP** — целиком перенесённый [AMQPush](https://github.com/DEADover/AMQPush):
  отправка с шаблонами, переменными, пачками и CSV, приём с селекторами и
  записью, просмотр и чистка очередей, переливка сообщений между брокерами,
  клиенты брокера, история и статистика. Семь экранов в боковом меню, а брокер
  задаётся в профиле стенда рядом с адресом шины: узел и учётные данные, если
  их не менять, берутся у неё.
- ⚖️ **Сравнение двух стендов** — чего нет на бою из того, что есть на тесте,
  где разошлись константы и где по-разному настроена трассировка. Только
  чтение: оба стенда читаются за секунду.
- ⚙️ **Обслуживание** — модули, точки восстановления, запуск и остановка
  доменов. Константы всех трёх уровней правятся на месте, а по всему стенду
  ищутся по значению и заменяются массово с предпросмотром: адрес смежной
  системы, записанный в двух сотнях доменов, меняется одной операцией.

Интерфейс двуязычный (English / русский), со светлой и тёмной темой.

## Что происходит под капотом

**Наружу уходит только то, что вы попросили.** Приложение ходит на введённый
вами адрес и никуда больше: своих серверов и телеметрии нет. Подключения лежат
на вашей машине, пароль сохраняется только с явного разрешения.

**Трассировка правится выгрузкой и загрузкой.** Отдельных методов для объектов
трассировки в API шины нет, поэтому режим устроен так: забрать выбранные домены
(`GET /api/domains/export/archive?exclude=history,models`), поправить файлы,
отправить обратно (`POST /api/domains/import/archive`). Тот же путь, что
и в файловом режиме, просто без ручного скачивания архива.

Выгрузка идёт пачками по 10 доменов, по четыре разом: шина собирает архив
целиком до отправки, и у 256 доменов первый байт приходит через две с половиной
минуты. Пачками — 150 доменов за 26 секунд вместо 64, со счётчиком.

Что и каким методом читается — в [docs/fesb-api.md](docs/fesb-api.md), включая
методы, которые отвечают не то, что обещают.

## Как начать

Скачайте сборку из [релизов](https://github.com/DEADover/FESB-Toolkit/releases):
Windows x64 (NSIS, MSI, портативный exe) или macOS на Apple Silicon. Дальше —
либо перетащите в окно папку выгрузки, либо заведите подключение: узел и порт
(по умолчанию 8181), схему и `/manager` приложение подберёт само.

Из исходников — [Node 20+](https://nodejs.org) и [Rust 1.82+](https://rustup.rs):

```bash
git clone https://github.com/DEADover/FESB-Toolkit
cd FESB-Toolkit
npm install
npm run dev            # разработка
npm run build          # сборка под текущую систему
npm test && npm run test:rust
```

## Стек

Tauri 2 · Rust · React 19 · TypeScript · Vite · Tailwind

Rust держит всю работу с файлами и сетью, интерфейс получает готовые структуры
и прямого доступа к диску не имеет. Разбор XML, сборка архивов и запись `.xlsx` —
свои.
