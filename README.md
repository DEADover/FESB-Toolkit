# FESB Settings Editor

Кроссплатформенный (Windows / macOS / Linux) инструмент для работы с конфигурацией
интеграционной шины **FESB**.

Интерфейс двуязычный (English по умолчанию, есть русский), со светлой и тёмной темой
и режимом следования за настройкой ОС.

## Разделы

| Раздел | Подраздел | Состояние |
| --- | --- | --- |
| **Configuration Files** (файлы конфигурации) | **Trace Configuration** — домены, их СОПС и объекты трассировки на одном экране | реализовано |
| **API** | **Connection** — адрес шины, учётная запись, состояние модулей | реализовано |
| **API** | **Domains** — домены сервера, выбор и выгрузка в редактор | реализовано |
| **API** | **Queues** — менеджеры очередей и их очереди | реализовано |
| **API** | **Modules** — состояние модулей, запуск и перезапуск | реализовано |
| **API** | **Constants** — константы приложения, брокера и доменов | реализовано |
| **API** | **Logs** — журналы сервера с фильтрами | реализовано |
| **API** | **Domain Map** — весь сервер на одном экране: ошибки, незапущенные СОПС | реализовано |
| **API** | **Routes** — СОПС сервера с живыми счётчиками и схемами | реализовано |

## Что умеет альфа-версия

Экран **Trace Configuration** — единая таблица: домен, его объекты трассировки и его СОПС.
Строка домена раскрывается прямо в таблице, не ломая колонки: сначала карточка домена
(GUID, режим запуска, состояние, путь к файлу), затем объекты трассировки с чекбоксами,
затем СОПС с именами схем и признаком включённой трассировки.

Версия шины читается из файла `version` рядом с выгрузкой (например, `V8.6.461`)
и показывается в заголовке раздела рядом с папкой и количеством доменов.

Массовая правка объектов трассировки в выгруженной конфигурации:

1. Открываете выгрузку одним из трёх способов: перетаскиванием в окно, кнопкой
   **Select Folder** или **Open ZIP**. Нужна папка, внутри которой лежат `domains`
   и `version`, — либо zip с той же структурой внутри.

   Архив приложение распаковывает во временную папку само и дальше работает с ней;
   собранный обратно zip предлагается сохранить рядом с исходным.
2. Приложение рекурсивно обходит вложенные папки и в каждой ищет пару
   `settings.properties` + `domain.xml`.
3. Из `settings.properties` берётся имя домена (`fesb.domain.name`), из `domain.xml` —
   bean-ы трассировки (`factor:type="TRACE"`) и их `broker`, `queue`, `traceMode`,
   из `routes/route-*.xml` — СОПС и их атрибуты `factor-trace` / `factor-trace-config`.
4. Строится таблица доменов с поиском (в том числе по именам СОПС), сортировкой
   и фильтрами по значению брокера. В колонке **Routes** видно «сколько схем
   используют трассировку / сколько их всего», а у каждого объекта трассировки —
   в скольких СОПС он используется.

   Если у домена несколько объектов трассировки и их значения различаются,
   в строке домена стоит **MULTI**; одинаковые значения показываются как есть.
   Остановленные домены приглушены, подробности — в подсказке при наведении.
   Узкая колонка с карандашом отмечает точкой записи, изменённые в текущей сессии;
   фильтр **Only Changed** оставляет в таблице только их.
5. Отмечаете нужные домены (или отдельные bean-ы), задаёте новое имя брокера,
   имя очереди и/или режим трассировки и жмёте **Apply**.
   Пустое поле остаётся без изменений.
6. Рядом с каждым изменённым `domain.xml` создаётся резервная копия `.bak`,
   после чего показывается отчёт: что изменено, что пропущено, где ошибки.
7. Кнопка **Build Configuration ZIP** собирает архив конфигурации
   для обратной загрузки в шину.

## Схемы СОПС

Имя любого СОПС в раскрытой строке домена — ссылка: по клику открывается схема
маршрута во весь экран.

Схема читается **слева направо**, как идёт сообщение: круг точки входа, задачи
обработки, ромбы ветвлений, круги завершения. Ветки расходятся по вертикали —
у каждой своя плашка с условием — и сводятся обратно в ромб слияния; ветка,
которая обрывается остановкой или исключением, никуда дальше не ведёт. Блок
«Попытка» показывает тело отдельно от обработчиков ошибок, а вложенные потоки —
разделение, цикл, фильтр — рисуются рамкой внутри общего потока. Цветом выделено
главное: вход, отправки наружу, ветвления и ошибки; у шагов с адресом показан
транспорт (`eik-ed`, `localmq`, `sql`).

Схему **тянут мышью за пустое место**, колесо приближает и отдаляет — относительно
курсора, а не центра. При открытии схема вписывается в окно целиком, кнопка
процентов возвращает этот вид. Самая большая СОПС корпуса — 53 шага в одну линию —
видна целиком на 16%, дальше читается зумом.

Подписи берутся из самой схемы — те же `factor-name`, что видны в редакторе
шины, а не имена элементов Camel. Под название в карточке всегда отведены две
строки: иначе длинное имя обрезалось бы посередине буквы, а карточки скакали бы
по высоте.

Клик по шагу открывает справа его карточку: сводка таблицей — шаг, компонент,
транспорт, исключения и все атрибуты, — а под ней полный адрес, выражение
или скрипт целиком и описание.

Разбор проверен на всём корпусе: 2355 схем, 26 664 шага, каждая начинается
с точки входа, и ни одно выражение не превратилось в отдельный шаг
(`cargo test --test corpus parses_every_route -- --ignored`).

## Режим API

Второй способ работы — напрямую с сервером, без ручной выгрузки и загрузки файлов.

### Быстрое переключение и статус

В шапке приложения, на любом экране, живут два элемента. Первый — переключатель
стенда: он показывает имя текущего подключения, его среду и цветом точки —
состояние связи. Из его списка, разложенного по средам, переключаются одним
кликом; профиль без сохранённого пароля помечен ключом и ведёт туда, где его
спросят.

Второй — журнал: что приложение сделало и что у него не получилось.
До сих пор ошибка жила на том экране, где случилась, и пропадала при
переключении, а массовые операции идут минутами и через несколько экранов.
Теперь подключение, чтение выгрузки, применение правок, отправка, сверка
и сборка архива оставляют по записи, и к ним можно вернуться.

### Подключения

Экран **Connection** открывается шестерёнкой у заголовка раздела **API** —
это настройка, а не повседневная вкладка. Это список стендов, разложенный по средам: разработка, тест,
предпрод и бой. Профиль хранит название, адрес менеджера (`http://localhost:8181/manager`,
можно просто `localhost:8181` — путь подставится сам), пользователя и пароль.
Профили заводятся, правятся и удаляются прямо здесь; **Test Connection** проверяет
связь, ничего не открывая, а **Connect** делает подключение текущим.

Пароль сохраняется только по явной галочке **Remember Password**: хранилище
не шифруется, и на общей машине его лучше не включать. Отсюда же следует
ограничение автоподключения — **Connect To The Last Used Server On Start** работает
только для профиля с сохранённым паролем, и если пароля нет, приложение прямо
об этом говорит, а не молчит.

Боевой стенд виден с одного взгляда: у среды свой цвет, у профиля с `prod` —
отдельное предупреждение в карточке, а метка среды показывается в заголовке
на всех экранах API и на экране трассировки, когда конфигурация взята с сервера.

У открытого подключения видно, кто мы, какие у нас роли и права, сколько
на сервере доменов и какие модули запущены. Если учётной записи не хватает прав
`DOMAIN_VIEW_ALL`, `DOMAIN_EXPORT_ALL` или `DOMAIN_IMPORT`, об этом сказано сразу.

На экране **Domains** виден список доменов сервера с поиском и фильтром по активным.
Отмечаете нужные и жмёте **Download Selected** — приложение забирает их и открывает
в обычном экране **Trace Configuration**. Есть и **Download All**, но выгрузка всего
сервера занимает несколько минут, тогда как несколько доменов приходят за секунду.

Дальше всё как в файловом режиме: правка, `.bak`, отчёт. К кнопке сборки архива
добавляется **Send To Server** — она отправляет обратно только изменённые (или только
выбранные) домены. Галочка **Reload Domains After Import** заставляет шину перечитать
конфигурацию сразу; без неё запущенные домены продолжат работать со старой
до перезапуска.

Рядом — **Compare With Server**. Импорт отвечает «200» и тогда, когда сохранилось
не всё, поэтому после отправки приложение читает те же домены обратно и сравнивает
значения трассировки со своими файлами: либо «совпали все N значений», либо таблица
расхождений с колонками «в ваших файлах» и «на сервере». Сверку можно запустить
и отдельно, ничего не отправляя, — чтобы увидеть, разошлась ли конфигурация.

В списке доменов есть запуск, остановка и перезапуск. Шина умеет отказать,
ответив «200» и телом `false` — например, если у СОПС домена нет нужного
компонента; в этом случае приложение прямо говорит об отказе и отправляет
в журналы за причиной.

### Карта доменов

Два с половиной сотни доменов — это масштаб, на котором вопрос «где сейчас болит»
иначе не задать. Один запрос `GET /api/domains/statistics/all` отдаёт по каждому
домену число СОПС, сколько из них запущено, сколько сообщений прошло, сколько
упало и сколько висит в работе. Экран сортирует список по ошибкам, а не по
алфавиту, и отдельно отмечает домены, которые активны, но подняли не все свои СОПС.

### СОПС сервера

Домен слева, его маршруты справа, схема — по клику. У каждого маршрута видно
состояние и счётчики: обработано, ошибок, обработано ошибок, в работе,
минимальное, среднее и максимальное время. Оттуда же маршрут запускается,
останавливается и сбрасывает счётчики, а в шапке открытой схемы появляется
полоса живого состояния.

Тонкость: `GET /api/broker/routes` отдаёт **только запущенные** маршруты, и на
стенде с остановленными доменами он пуст. Поэтому состав берётся из выгрузки
одного домена — она приходит за доли секунды и складывается в отдельную папку,
не трогая открытую рабочую выгрузку, — а состояние читается по каждому маршруту
через `GET /api/broker/domain/{domain}/route/{guid}`: этот метод отвечает и для
остановленного.

### Точки восстановления

Живут рядом с модулями, на экране **Modules**: и то и другое — обслуживание
сервера, и последствия у обеих операций одинаково крупные. Снятая точка — это
снимок всей конфигурации; смысл прямой: снять её перед массовой правкой
трассировки и откатиться, если что-то пошло не так. Откат перезапускает модули
и теряет всё, что изменено после точки, поэтому спрашивает подтверждение.

### Остальные вкладки раздела

**Queues** — менеджеры очередей всех трёх видов (мультименеджер, расширенные,
удалённые) и их очереди с глубиной, потребителями и счётчиками. Значение
`broker`, которое пишется в `domain.xml`, показано ровно в том виде, в каком
оно туда попадает (`QME:EQM_MON`), и копируется одной кнопкой.

Эта вкладка связана с редактором трассировки: когда конфигурация взята
с сервера, в подсказки полей **New Broker Name** и **New Queue Name** попадают
настоящие менеджеры и очереди, а брокер, которого на сервере нет, помечается
предупреждением ещё до применения.

**Modules** — состояние всех модулей шины: работает или нет, выключен ли
в конфигурации, есть ли предупреждения и не ждёт ли модуль перезапуска.
Оттуда же он запускается, останавливается и перезапускается — остановка
и перезапуск спрашивают подтверждение, а для брокера отдельно предупреждают,
что вместе с ним встанут все домены.

**Constants** — константы приложения, брокера и любого домена: поиск,
правка, добавление и удаление. Домен выбирается по имени, а серверу уходит
его guid — по имени константы не находятся.

**Logs** — журналы сервера. Сервер отдаёт записи уже разобранными, поэтому
есть фильтр по уровню, по файлам и поиск по тексту. Длинное сообщение
разворачивается по клику **отдельной строкой во всю ширину окна**: внутри
колонки сообщений стектрейсу достаётся половина экрана и каждая его строка
ломается по два-три раза. Рядом кнопка копирования — трейс чаще нужен тикету,
чем глазам. Есть автообновление раз в десять секунд.

Что происходит под капотом и почему выбран именно такой путь — в
[docs/fesb-api.md](docs/fesb-api.md).

## Сборка архива

Архив повторяет структуру исходной выгрузки: в корне папка `domains` и файл `version`,
без обёртывающей папки. Если открыт корень выгрузки через API — там рядом лежат ещё
`conf`, `data`, `messages`, `resources`, — всё это переносится в новый архив как есть. Папки `.history` сохраняются как в оригинале, а вот резервные
копии `.bak`, которые создаёт само приложение, и системный мусор вроде `.DS_Store`
в архив не попадают — шине они не нужны.

Кнопка есть и в панели инструментов, и в отчёте сразу после применения изменений.
Если есть выделение или изменения, сделанные в этой сессии, приложение спросит,
что упаковать: изменённые домены, выбранные или весь экспорт.
Файл `version` включается в архив в любом случае.
По умолчанию архив предлагается сохранить рядом с папкой конфигурации, а не внутрь неё;
если всё же сохранить его внутрь выгрузки, сам себя в архив он не положит.

Проверено на настоящей выгрузке: 40 154 файла — ровно столько же, сколько в исходном
zip из шины, `unzip -t` без ошибок.

### Как выполняется замена

- `domain.xml` **не переформатируется**: правится только диапазон байтов самого значения,
  остальной файл остаётся байт-в-байт прежним. Это важно, потому что файл потом
  загружается обратно в шину.
- Перед записью значение перепроверяется: если с момента сканирования файл изменили
  извне, такое поле не трогается и попадает в отчёт с пометкой
  «Value Changed Since The Scan».
- Запись атомарная (временный файл + переименование) — оборванной записи не будет.
- Резервная копия — `domain.xml.bak`. Если она уже есть, создаётся
  `domain.xml.<дата-время>.bak`, так что предыдущая копия не затирается.
- Каталоги `.history` (старые версии файлов), `node_modules`, `.git` при обходе пропускаются.

### СОПС (схемы обработки потоков сообщений)

СОПС — это обычные route Apache Camel из `routes/route-*.xml`. Приложение читает у них:

- `factor-name` — имя схемы;
- `factor-trace` — включена ли трассировка;
- `factor-trace-config` — на какой объект трассировки она ссылается (иногда на несколько, через запятую).

Схемы показываются внутри раскрытого домена, поиск ищет и по их именам,
а фильтр «With Untraced Routes» оставляет только домены, где есть схемы
с выключенной трассировкой.

Отдельные точки маршрута (endpoint-ы) тоже могут нести собственный `factor-trace-config`
со встроенным JSON — такие переопределения приложение сейчас не показывает,
уровень схемы для задачи «где включена трассировка» достаточен.

### Особые случаи

- В домене может быть **несколько** bean-ов трассировки — тогда домен в таблице
  разворачивается в подстроки, а чекбокс домена выделяет их все сразу.
- У bean-а может не быть `broker` или `queue` (например, у `TraceToMemory`) —
  такое поле показывается как «No Property» и при применении пропускается.

## Стек

- **Tauri 2** — оболочка приложения, вся работа с диском в Rust
- **React 19 + TypeScript + Vite 8**
- **Tailwind CSS 4** — темы заданы CSS-переменными, светлая переопределяет тёмную

Фронтенд не имеет прямого доступа к файловой системе: он общается с Rust-командами
`scan_directory`, `apply_trace`, `write_text_file`.

## Разработка

```bash
npm install
npm run dev          # запуск приложения в режиме разработки
npm run build        # сборка установщика под текущую ОС
npm run test:rust    # тесты бэкенда
```

### Сборка под Windows

Кросс-компиляция Windows-инсталлятора с macOS у Tauri штатно не поддерживается,
поэтому сборка идёт на Windows-раннере GitHub Actions:
[`.github/workflows/build.yml`](.github/workflows/build.yml). Workflow запускается
на каждый push в `main` и вручную, прогоняет тесты бэкенда и выкладывает два артефакта:

| Артефакт | Что внутри |
| --- | --- |
| `fesb-settings-editor-windows-installer` | `.exe` (NSIS) и `.msi` |
| `fesb-settings-editor-windows-portable` | один `fesb-settings-editor.exe`, без установки |

```bash
gh workflow run build.yml          # запустить вручную
gh run download --name fesb-settings-editor-windows-portable
```

Установщик ставится в профиль пользователя, без прав администратора;
язык интерфейса установщика — английский или русский на выбор.

Portable-версия — это обычный собранный `exe`: он самодостаточен, настройки
(тема и язык) хранит в профиле пользователя. Единственная внешняя зависимость —
**WebView2 Runtime**, который встроен в Windows 10 (сборка 2004 и новее) и Windows 11.
На более старых системах его ставят один раз
[отдельным установщиком от Microsoft](https://developer.microsoft.com/microsoft-edge/webview2/).

Вёрстку можно смотреть без пересборки всего приложения: `npm run vite:dev`
и страница `/dev-preview.html` — это тот же интерфейс с заглушкой вместо IPC
Tauri. Настоящие вызовы там не работают, зато цикл правки занимает секунды,
а не минуту сборки.

То же самое на своей Windows-машине:

```bash
npm ci && npm run build
```

Проверка парсера на настоящей выгрузке конфигурации:

```bash
FESB_CORPUS=/путь/к/config-.../domains cargo test --manifest-path src-tauri/Cargo.toml --test corpus -- --ignored --nocapture
```

Проверка режима API на живом стенде — тест забирает домен, меняет `broker`,
отправляет обратно, сверяет результат и возвращает исходное значение:

```bash
FESB_URL=http://localhost:8181/manager FESB_USER=root FESB_PASSWORD=root cargo test --manifest-path src-tauri/Cargo.toml --test api -- --ignored --nocapture
```

## Структура

```
src/
  i18n/               словари en/ru и провайдер перевода
  components/         экраны Trace, Connection, Domains, Queues, Modules,
                      Constants и Logs, схема СОПС, отчёт, примитивы UI
  lib/api.ts          единственная точка вызова бэкенда
  lib/connection.ts   параметры подключения между запусками
  lib/rows.ts         группировка по доменам, фильтры, сортировка, сводки
  lib/theme.ts        светлая/тёмная/системная тема
src-tauri/src/
  xml.rs              общий сканер тегов и атрибутов с байтовыми смещениями
  properties.rs       разбор settings.properties
  domain_xml.rs       поиск TRACE-bean-ов и точных смещений значений broker/queue
  route_xml.rs        разбор СОПС: включена ли трассировка и на какой объект ссылка
  route_graph.rs      разбор СОПС в дерево шагов — из него рисуется схема
  scanner.rs          обход папок и сбор карточек доменов
  applier.rs          резервные копии и атомарная запись
  archive.rs          сборка и распаковка zip выгрузки
  fesb_api.rs         подключение, выгрузка и загрузка доменов через REST
  fesb_ops.rs         модули, очереди, константы и журналы через REST
  lib.rs              команды Tauri
```
